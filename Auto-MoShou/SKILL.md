# 魔兽世界自动建号（Auto-MoShou）

在真实桌面上用鼠标键盘自动控制，完成一个**由用户决定全部关键信息**的魔兽世界无限服角色创建：

- **不可修改项 + 姓名**：必须由用户从**全部可选项**中逐项指定，技能不携带任何固定模板、不替用户决定。
- **可创建后再改的项**：体型（性别）、外观细节、HD/SD 模型——Agent 直接采用默认或随机，只在用户主动指定时才按用户选择。

## 开始前：谁决定什么

收齐配置后才开始操作桌面。**不可修改项与姓名必须把该层全部合法选项列给用户选择**；用户给出的值不在选项表里时，先说明并请其重新选择，不要猜测。

**快速路径（用户一次性给全配置）**：如果用户第一句话就明确给出了规则集、阵营、种族、职业和姓名（例如「无限 PVP 服务器，部落男亡灵圣骑士，主名 X 副名 Y，不平衡就重来」），不必再逐层列全选项；先把这些值对照下表做合法性校验，复述一遍请用户确认即可。缺项、含糊或组合非法时再回退到逐项列全。只说「PVP 已默认选中，直接点」不算明确指定规则集，仍要问一句确认。

### A. 必须由用户指定（创建后不可修改 + 姓名）

#### 1. 规则集（不可修改）

把下面 5 项全部列出：

| 选项 | 规则 | 适合 |
|------|------|------|
| 普通（PVE） | 野外默认不可被敌对玩家攻击，PVP 需手动开启 | 新手、休闲、练级打本 |
| PVP | 争夺区域默认自由对抗，一个账号只能锁定一个阵营 | 喜欢野外阵营冲突 |
| RP（角色扮演） | 同 PVE，但命名与言行有严格规范 | 沉浸剧情、角色扮演 |
| RP-PVP | RP 规范 + 野外强制 PVP | 硬核扮演玩家 |
| 硬核（专家） | 一命模式，死亡即作废（开服时未开放，后续解锁） | 熟悉玩法的老手 |

> 规则集选定后基本无法转换；不同规则集之间不能组队打副本（仅战场跨规则集匹配）。必须让用户明确确认，不能沿用「PVP 默认」。

#### 2. 阵营（不可修改）

列出：**部落** / **联盟**。

> PVP 规则集下阵营是硬锁：选定后不能在该规则集建另一阵营角色。天裔分支随阵营绑定（塑风者→部落、高阶会→联盟）。

#### 3. 种族（不可修改，按阵营列出全部 5 个）

- **部落**：兽人、亡灵、牛头人、巨魔、塑风者天裔（需「天裔英雄包」或更高礼包）
- **联盟**：人类、矮人、暗夜精灵、侏儒、高阶会天裔（需「天裔英雄包」或更高礼包）

只列出用户所选阵营的 5 个种族，并说明天裔需要礼包；用户选择未解锁的天裔时先提醒确认，不要自行替换。

#### 4. 职业（不可修改，按种族列出全部可选项）

用户选好种族后，把该种族的**全部可选职业**列给用户：

| 阵营 | 种族 | 全部可选职业 |
|------|------|--------------|
| 部落 | 兽人 | 战士、猎人、潜行者、萨满祭司、法师、术士 |
| 部落 | 亡灵 | 战士、圣骑士、潜行者、牧师、法师、术士 |
| 部落 | 牛头人 | 战士、猎人、萨满祭司、德鲁伊 |
| 部落 | 巨魔 | 战士、猎人、潜行者、牧师、萨满祭司、法师、术士 |
| 部落 | 塑风者天裔 | 战士、猎人、潜行者、萨满祭司、德鲁伊 |
| 联盟 | 人类 | 战士、圣骑士、猎人、潜行者、牧师、法师、术士 |
| 联盟 | 矮人 | 战士、圣骑士、猎人、潜行者、牧师、萨满祭司 |
| 联盟 | 暗夜精灵 | 战士、猎人、潜行者、牧师、德鲁伊 |
| 联盟 | 侏儒 | 战士、潜行者、牧师、法师、术士 |
| 联盟 | 高阶会天裔 | 战士、猎人、潜行者、法师、德鲁伊 |

用户想看全局组合时可给出整张表；**实际选择时只给当前种族的合法职业清单**。

#### 5. 姓名（等同不可修改，必须用户给）

- 采用 **名 + 姓** 双段命名：先问「主名」，再问「副名」（副名可选，用户不给就留空）。
- **主动要求用户同时提供 1-2 个备选名**（建议给足 2 个）：重名判定看完整名+姓组合；RP 规则集对名字合理性要求尤其严格；无限服目前没有改名服务，名字实际上等同锁定。
- 名字原样输入，不翻译、不改写、不自行编造；备选名按顺序使用。

### B. 可由 Agent 默认或随机（创建后可修改）

以下项目**不需要向用户逐项询问**，Agent 直接采用默认或随机；用户主动指定时按用户选择：

- **体型（性别）**：体型 1（男性模型）/ 体型 2（女性模型），默认或随机选一个；按钮在外观页顶部中间。
- **模型精度**：高清（HD）/ 标清（SD），默认或随机；只影响外观与动作精度。
- **其他外观**：发型、发色、肤色、脸型、纹身、瞳色、耳饰默认不动；用户想随机时可以随机。
- **副名显示、幻化、天赋专精**等属于创建后设置，不在建号阶段询问。

## 配置确认

收齐 A 类必须项后，把用户所选的**规则集 / 阵营 / 种族 / 职业 / 姓名（含备选名）**和 B 类默认/随机结果**一次性复述即可，不逐项询问、不等待用户确认**，随后立即开始操作，适合用户挂机运行。运行中不得更换用户选择；项与项冲突（种族不在所选阵营、职业不合法、天裔未解锁）才停下报告，请用户重新选。

## 前置硬约束（最高优先级）

> **不需要虚拟桌面**：该技能明确限定在真实桌面 `main` 上操作，禁止切到 pip 或豆包虚拟桌面；全程只点游戏窗口，不碰其他程序、不点右上角关闭按钮。我先截屏看一下当前桌面和游戏客户端状态。

**每次任务开始的第一步（强制）**：先截屏观察当前桌面和游戏客户端状态，确认处于真实桌面 `main`、游戏窗口可见且可操作，然后再进入配置收集和状态机；不要凭记忆中的坐标直接点击。如确需显式指定桌面，只允许 `cu.switch_desktop("main")`，**禁止** `cu.switch_desktop("pip")`、豆包虚拟桌面或任何虚拟桌面切换。

### 提高速度：单帧复用 + 状态驱动（默认执行方式）

1. **一帧一动作，不重复截屏**：进入一个界面后截一次屏，确认目标文字/图标与坐标（0–1000 归一化）；执行动作后的截图**直接作为下一步的点前截图**，不再额外截一遍。
2. **缓存当前界面元素**：同一界面内按钮位置和文字只识别一次；只有界面切换、窗口移动或弹窗出现才重新定位。
3. **不空等 1 秒**：点击/输入后立即按界面状态判断（选中高亮、按钮变化、页面跳转）；需要动画时只等 0.3–0.6 秒。姓名用整段填入，不逐字敲。
4. **固定等待是上限，不是下限**：重连/规则页标称 4 秒、回退标称 3 秒——界面提前就绪就立刻继续，不等满。
5. **失败重试更快**：同一动作没生效时等 0.5 秒重截屏重试，**同一动作最多 5 次**；仍失败先尝试备用定位/重新聚焦游戏窗口，再失败就走「退出重进」流程，**不在这里停机**。每成功推进一次，重试计数清零。

### 续跑与容错（用户可能已经手动操作过）

- **先判断当前在哪一步，不从第 0 步盲跑**：每次开始或重试后截屏识别当前实际阶段（登录 / 规则页 / 角色创建 / 外观 / 命名 / 结果弹窗 / 角色列表），从当前阶段继续。
- **已选中且和配置快照一致 → 直接跳过**：例如用户已手动选好 PVP、部落、亡灵、圣骑士或体型，不要再点一次，避免把单选/开关点成相反值。
- **已选中但和配置不一致 → 提交前自动改回用户配置**，不询问、不重复确认；只有已经提交且属于不可修改项才停下报告。
- **输入框已有内容**：与主名/副名一致就保留；不一致则清空后整段填入用户给的名字，不逐字敲。
- **已经在角色列表 / 创建完成界面且配置一致** → 直接判成功，不再重复建号。
- 用户中途手动推进了几步、或界面停在半途：以当前画面为准续跑；**无法判断当前阶段时先退出重进再试**，仍无法判断才停下说明，不重置、不从头覆盖。

### 防卡死（卡住就退出重进，不停机）

- **心跳播报（纯通知，不等待用户回复）**：一次完整尝试开始后，若 30 秒内没有进入下一阶段或完成提交，就每 30 秒播报一次「仍在 XX 阶段，正在继续」；进入新阶段即重置计时。
- **一次完整尝试**（登录 → 提交）超过 3 分钟仍无结果：主动回退重来，不算停止。
- **「阵营人口不平衡」弹窗再次出现 = 正常重试**：不计数、不询问，回登录页继续，**循环到创建成功为止**。
- **同一步骤无法越过、界面长时间无变化**：不按次数或秒数停机；用游戏界面的「后退 / Esc」退出当前界面，回到登录页重新进入，复用同一份配置快照重试。不要点窗口右上角关闭按钮。
- 退出也失败时，再试一次「重新连接」或重新聚焦游戏窗口；仍不行才停下报告当前画面——这是最后手段，不是常规阈值。
- 不再设置 5 次/120 秒/15 分钟等任何停机阈值，也不设人口不平衡重试次数上限。未知弹窗、配置冲突、备选名耗尽、不在 main：立即停下，不等超时、不盲点。
- 全程只在真实桌面 `main` 操作；发现当前不在 main 时立即停止，切回 main 并重新截屏确认。
- 不要点窗口右上角关闭按钮；只在游戏窗口范围内操作，不触碰其他桌面程序。
- 规则集、阵营、种族、职业、姓名以用户确认的结果为准；体型、外观、HD/SD 可按默认或随机执行，用户有指定时按指定。

## 主流程状态机

以下步骤按「单帧复用 + 状态驱动」执行：同一界面只截一次屏，动作后立即看状态，固定秒数只是上限。

0. **规则集选择**（战网侧）：用户已选成目标规则集就跳过；否则按用户所选点选。确认后不可更改。
1. **登录界面**：已经在规则页/创建页则直接跳到对应阶段；否则点中间「重新连接」，4 秒是上限。
2. **阵营 / 规则页**：PVP 等规则和阵营**已选中且正确就跳过，不重复点**；不符才改成用户所选，再点右下角「选择」，下一界面出现即继续。
3. **角色创建界面**：按用户所选逐项检查，已选对的直接跳过：
   1. 阵营 → 种族（在对应阵营列里找用户指定头像）
   2. 职业（底部职业排，按文字/图标辨认，不按固定序号）
4. **外观页**：已在外观页就直接操作；否则点右下角「自定外观」箭头进入。体型 1/2 与 HD/SD 已正确就跳过，未指定才默认/随机；其他外观默认不动。
5. **名字输入**：框内已有用户指定的名字就保留；否则清空后整段填入主名/副名（没有就留空）。若提示不可用，按备选名顺序依次尝试；备选名耗尽才停下报告。
6. 点右下角【完成】，等待结果弹窗或进入完成界面。

## 不平衡弹窗重试分支

若提交后弹出“由于阵营人口不平衡”提示：

1. **先模拟真人操作：连续按回车 5–10 次**，每次间隔 1–3 秒（可随机化，更像真人）；**每次按键后播报一次「正在模拟回车 n/10…」**（纯通知，不等回复）。弹窗若已消失，就从当前画面继续，不再点「确定」。
2. 弹窗仍在时再点中间「确定」。
3. 点左下角「后退」按钮（第一次）。
4. 点左下角「后退」按钮（第二次）。
5. 第三次点后退：按钮位置往下移一点点——此前坐标偏上点不到，需在按钮实际可见区域偏下位置点击。
6. 等 3 秒为上限；登录界面一出现就立刻继续，不必等满。
7. 从主流程第 1 步重新开始，**直接复用用户最初确认的配置快照和名字队列**，不重新询问、不重新确认；B 类项目沿用同一份默认/随机结果，循环直到创建成功。
8. 每轮回退后截屏确认回到登录页即可重跑。**再次看到该弹窗算正常重试，不计数、不询问、不停机**。

## 成功判定

- 不再出现“阵营人口不平衡”弹窗，角色进入角色选择列表或创建完成界面。
- 逐项核对与用户确认结果一致：规则集、阵营、种族、职业、主名、副名。
- 体型、模型精度若为默认/随机则核对界面成功应用；用户有指定时也须逐项一致。
- 任一项不一致不得报成功；未提交前可返回修改，已提交且属于不可修改项时按失败流程后退重来或停下报告。

## 界面识别与坐标注意

各界面特征、按钮位置、坐标坑与异常处理见 [references/flow-states.md](references/flow-states.md)。**不依赖固定头像/职业序号**；一切以当前截屏识别到的文字和图标为准。

## 运行方式

本技能不含独立可执行脚本；由 Agent 在 `computer_use_tool`（`plane="cu"`）单元内调用 `seed_computer_use`，按上述状态机逐步截屏、点击、输入、等待。配置确认阶段不需要操作桌面，且必须先完成。
